## Diagnosis

GitHub Actions run [44151162238](https://github.com/uBruckhaus/macos-maprisma/actions/runs/44151162238)
(eb6b59c, macos-15-arm64, Flutter 3.50.0) successfully ran `pod install`, then
failed with `diff: /Podfile.lock: No such file or directory`.

The project-level Debug and Release configurations load
`Runner/Configs/{Debug,Release}.xcconfig`, which load the corresponding
`Flutter/Flutter-{Debug,Release}.xcconfig`. Profile uses Release. Runner's
target-level AppInfo.xcconfig adds identity settings without overriding those
inherited settings. The Podfile maps Debug, Release and Profile correctly.

Both Flutter xcconfigs were missing the optional Pods-Runner include. Thus
`PODS_PODFILE_DIR_PATH` and `PODS_ROOT` were undefined when the manifest phase
generated by `pod install` ran. Its `${PODS_PODFILE_DIR_PATH}/Podfile.lock`
expanded to `/Podfile.lock`. The phase is absent in the checked-in pbxproj
because CocoaPods adds it during integration. Restore the standard includes;
do not hardcode Pods paths or bypass the manifest check. Keep the existing
CocoaPods/SPM coexistence; migrating the custom Podfile is separate work.

## Changes

- Restore Debug and Release Pods includes before Flutter's generated settings.
- Package in a temporary directory and preserve the previous dist artifact until
  the worker, assets, no-Python bundle gate and signatures pass. Read the add-on
  version from the Flutter pubspec rather than the Python reference.
- Require native arm64 builds and check both executables contain arm64. The
  Flutter app can also contain x86_64, but its standalone worker is arm64 only.
- Sign the added worker, then the outer app. Keep Xcode's framework signatures
  intact instead of re-signing them with `--deep --force` and app entitlements.
- Validate the source install and staged copy before replacing the old app;
  retain it for rollback if activation fails. Remove only quarantine, and make
  elevated system installs root-owned. Diagnose missing `--addons` arguments.
- Pin CI to the SDK from the failed run, check build tools, verify Runner's
  resolved Pods settings and matching lockfiles, then extract and verify the ZIP,
  its Release entitlements, architectures and runnable compiled worker.

Release.entitlements already disables App Sandbox and allows microphone input,
matching Info.plist's microphone usage text. The release is AOT and does not
require the debug JIT entitlement. No Developer ID signing, hardened runtime or
notarization is introduced; this remains a local/CI ad-hoc package.
